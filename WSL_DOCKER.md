# WSL and Docker Setup Guidelines

Ubuntu WSL and Docker Setup for Assignment Work

## Purpose

This document provides basic guidance for Ubuntu WSL setup, Docker usage with WSL, and assignment-specific expectations for running Node.js and Docker commands inside WSL. In this organization, all software installation must be handled through the IT Helpdesk unless IT has explicitly approved self-service installation.

## Scope

This guideline applies to users who need to:
- Request or validate WSL installation.
- Use Ubuntu WSL for local development.
- Use VS Code with a WSL workspace.
- Install or validate Node.js and npm inside WSL.
- Use Docker from inside WSL for assignment work.
- Understand what must not be run directly from Windows PowerShell or Windows Command Prompt for WSL-based assignments.

## Prerequisites
- You have a company-approved laptop or desktop.
- You have permission to use WSL on your device.
- You have permission to use Docker Engine inside Ubuntu WSL.
- Virtualization support is enabled on the device, where required.
- You have network access to GitHub, package registries, Docker image registries, and assignment APIs as required.

## Node.js and npm in WSL

- Node.js and npm must be available inside Ubuntu WSL for WSL-based assignments.
- Run these commands inside Ubuntu WSL:

```bash

node -v
npm -v

```

- If these commands fail in WSL, contact IT Helpdesk or follow the IT-approved Node.js installation process for WSL. Windows Node.js is not sufficient for assignments that require WSL execution.
- Typical validation commands after installation:

```bash

sudo service docker start
docker --version
docker ps

```

- If systemd is enabled in your WSL distribution, IT may use systemctl instead of service:

```bash

sudo systemctl start docker
sudo systemctl status docker

```

- Run these commands inside Ubuntu WSL:

```bash

docker --version
docker ps

```

- If docker ps works inside Ubuntu WSL, Docker is ready for assignment use.
- If either reference conflicts with company policy, follow company policy.

## Quick Verification Checklist

| Check	| Command	| Expected Result |
|:------|:--------|:----------------|
| WSL distribution | ``wsl --list --verbose``	| Ubuntu is listed and uses WSL 2 |
| Linux shell	| ``uname -a`` | Linux environment details are shown |
| Project path | ``pwd`` | Path is under /home/<username>/... |
| Node.js	| ``node -v``	| Node version is displayed inside WSL |
| npm	| ``npm -v`` | npm version is displayed inside WSL |
| Docker CLI | ``docker --version``	| Docker version is displayed inside WSL |
| Docker daemon	| ``docker ps``	|Container list appears without daemon errors |

## Responsible Usage Guidelines

- When using WSL and Docker:
  - Do not put credentials, API keys, passwords, tokens, or certificates into Dockerfiles, prompts, screenshots, or submitted files.
  - Do not copy client data or confidential business data into assignment containers.
  - Use only approved base images and package sources where required by company policy.
  - Review Dockerfiles generated by AI before running them.
  - Do not run privileged containers or mount sensitive host directories unless explicitly approved.
